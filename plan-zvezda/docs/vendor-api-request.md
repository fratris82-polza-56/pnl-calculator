# Запрос разработчикам аптечного ПО: передача данных о продажах через API

> Готовый текст для отправки вендору. Ключ интеграции (X-Intg-Key) передать
> отдельно защищённым каналом — не включать в письмо.

---

Тема: Запрос на интеграцию — автоматическая передача данных о продажах

Добрый день!

Просим реализовать (или сообщить, если уже есть) автоматическую передачу данных
о продажах из вашей системы в нашу аналитическую систему «План-звезда».

## Вариант А (предпочтительно): вы передаёте нам (push)

**Endpoint:** `POST http://zvyagin-ai.polza.ru:8080/api/integration/sales`
**Заголовок:** `X-Intg-Key: <ключ — передадим отдельно>`
**Формат:** JSON, кодировка UTF-8.

```json
{
  "pharmacy_id": 1,
  "sales": [
    {"doc_id": "Ч-1042", "d": "2026-09-29", "employee_name": "Иванова Анна Сергеевна", "amount": 1250.50, "margin": 310.20},
    {"doc_id": "Ч-1043", "d": "2026-09-29", "employee_name": "Иванова Анна Сергеевна", "amount": 840.00, "margin": 196.40}
  ]
}
```

**Поля:**

| Поле | Обяз. | Описание |
|---|---|---|
| `pharmacy_id` | да | Код аптеки: 1 — Азовская, 2 — Юбилейный, 3 — Проспект Мира, 4 — Маяковская, 5 — Пятницкое (согласуем под ваши внутренние коды) |
| `sales[].doc_id` | нет | Номер чека. Нужен для защиты от дублей: повторная передача строки с тем же `doc_id`+дата+аптека пропускается без задвоения. Без `doc_id` строки считаются сводкой дня и ЗАМЕНЯЮТ итог дня сотрудника |
| `sales[].d` | да | Дата продажи, `ГГГГ-ММ-ДД` |
| `sales[].employee_name` | нет | ФИО продавца/провизора, как в кадровых данных (полностью, не инициалы) — мы сопоставляем без учёта регистра и лишних пробелов |
| `sales[].amount` | да | Сумма строки/чека в рублях |
| `sales[].margin` | нет | Валовая прибыль (наценка) по строке. Если не считаете — передавайте закупочную цену, согласуем |

**Одна партия = одна смена/день одной аптеки.** Допустимо слать и построчно чеки
(тогда с `doc_id`), и итоги по сотрудникам за день (тогда без `doc_id`).

**Периодичность:** раз в сутки после закрытия смены (снятия Z-отчёта) за прошедший
день. При недоступности нашего сервиса — повторные попытки до успеха.

**Ответ нашей системы:**

```json
{"ok": true, "accepted": 120, "duplicates": 3, "mapped": 117, "unmapped": ["Петров П.П."]}
```

`unmapped` — ФИО, не сопоставленные с нашим справочником: мы их сохраним и
разберём вручную, дублирования факта не произойдёт.

**Ретроспектива:** после настройки просим одной (или помесячной) выгрузкой
передать продажи с 01.09.2026 — заполним факт по плану Q4.

## Вариант Б: мы забираем сами (pull)

Если POST из вашей системы неудобен:

1. У вашего ПО есть собственный API или выгрузка? Пришлите схему и доступ —
   мы будем забирать данные сами.
2. Ежедневный файл (CSV/XML/DBF) с полями: дата, номер чека, ФИО сотрудника,
   сумма, наценка — по email/SFTP/общему ресурсу. Формат пришлите любой —
   адаптируемся под ваш.

## Тестирование

Пришлите тестовую партию за один закрытый день по одной аптеке — проверим
сопоставление ФИО и итоги, дадим обратную связь в тот же день.

Ключ интеграции передадим защищённым каналом после согласования формата.
